# Spring Bean 加载方式与核心原理

> 覆盖：原理篇 139~155，只保留核心知识点 + 关键代码。

## 一、Bean 注册方式（11 种）

### 1. XML `<bean>` 声明式
- 在 `beans.xml` 中用 `<bean>` 标签定义，容器解析生成 `BeanDefinition` 后实例化。
- 老旧项目、第三方类场景，SpringBoot 已淘汰。

```xml
<bean id="bookService" class="com.example.bean.BookService"/>
```
```java
ClassPathXmlApplicationContext ctx = new ClassPathXmlApplicationContext("beans.xml");
```

---

### 2. XML + component-scan 混合
- XML 中开启 `<context:component-scan base-package="..."/>`，被扫描包下 `@Component/@Service` 类自动注册。
- XML/注解混合过渡方案。

```xml
<context:component-scan base-package="com.example.bean"/>
```
```java
@Service  // 被扫描后自动注册
public class UserService { }
```

---

### 3. @ComponentScan + @Component + @Bean（纯注解，主流）
- `@ComponentScan` 替代 XML 扫描（`@SpringBootApplication` 已包含）。
- `@Component/@Service`：标记**自己写的类**。
- `@Bean`：写在配置类方法上，注册**第三方类**（无法加 `@Component` 的类）。

```java
@Service
public class OrderService { }       // 自己写的 → @Service

public class DruidDataSource { }    // 第三方 → 无法改源码

@Configuration
public class AppConfig {
    @Bean                           // 将第三方类注册为 Bean
    public DruidDataSource druidDataSource() {
        return new DruidDataSource();
    }
}
// 容器：new AnnotationConfigApplicationContext(AppConfig.class)
```

---

### 4. @Import(普通 Class)
- 直接注册无注解类，支持三类入参：普通 Class、ImportSelector、ImportBeanDefinitionRegistrar。
- 场景：第三方组件、自定义 starter。

```java
@Configuration
@Import(RedisService.class)   // 无需 @Component 即可注册
public class ImportConfig { }
```

---

### 5. @Import(ImportSelector) — 批量条件导入
- 实现 `selectImports()` 返回**全类名数组**，批量注册；可根据条件动态选择。
- `@EnableTransactionManagement`、`@EnableWebMvc` 底层都是它。

```java
public class MyImportSelector implements ImportSelector {
    public String[] selectImports(AnnotationMetadata metadata) {
        return new String[]{"com.example.MqService", "com.example.OssService"};
    }
}
@Configuration
@Import(MyImportSelector.class)
public class SelectorConfig { }
```

---

### 6. @Import(ImportBeanDefinitionRegistrar) — 手动注册 BeanDefinition
- 拿到 `BeanDefinitionRegistry`，手动构建 `BeanDefinition`，可自定义作用域、构造参数。
- **Mybatis `@MapperScan` 底层核心**。

```java
public class MyRegistrar implements ImportBeanDefinitionRegistrar {
    public void registerBeanDefinitions(AnnotationMetadata metadata,
                                        BeanDefinitionRegistry registry) {
        BeanDefinition bd = BeanDefinitionBuilder
                .genericBeanDefinition(RabbitMqService.class).getBeanDefinition();
        registry.registerBeanDefinition("rabbitMqService", bd);
    }
}
@Configuration
@Import(MyRegistrar.class)
public class RegistrarConfig { }
```

---

### 7. ctx.register() 运行期动态注册
- `refresh()` 之前调用 `ctx.register(Class)`，纯代码驱动，可配合条件判断。

```java
AnnotationConfigApplicationContext ctx = new AnnotationConfigApplicationContext();
ctx.register(MongoService.class);  // refresh 前注册
ctx.refresh();
```

---

### 8. FactoryBean — 复杂对象工厂
- `BeanFactory` 是容器；`FactoryBean` 是制造 Bean 的工厂。
- `getObject()` 返回最终产品；`getBean("&name")` 获取 FactoryBean 本身。
- 场景：Mybatis `SqlSessionFactoryBean`、连接池。

```java
public class HttpClientFactoryBean implements FactoryBean<HttpClientService> {
    public HttpClientService getObject() { return new HttpClientService(); }  // 产品
    public Class<?> getObjectType() { return HttpClientService.class; }
}
// ctx.getBean("httpClientFactoryBean")         → HttpClientService
// ctx.getBean("&httpClientFactoryBean")        → HttpClientFactoryBean
```

---

### 9. BeanDefinitionRegistryPostProcessor — 全局后置处理器
- 继承 `BeanFactoryPostProcessor`，在所有 BeanDefinition 加载完、实例化前执行。
- 可新增/修改/删除 BeanDefinition，全局生效。
- vs `ImportBeanDefinitionRegistrar`：后者随 `@Import` 触发（局部），前者全局后置（优先级更高）。

```java
@Component
public class MyProcessor implements BeanDefinitionRegistryPostProcessor {
    public void postProcessBeanDefinitionRegistry(BeanDefinitionRegistry registry) {
        BeanDefinition bd = BeanDefinitionBuilder
                .genericBeanDefinition(ElasticSearchService.class).getBeanDefinition();
        registry.registerBeanDefinition("esService", bd);
    }
    public void postProcessBeanFactory(ConfigurableListableBeanFactory bf) { }
}
```

---

### 10. Spring SPI（SpringFactoriesLoader）
- 读取 `META-INF/spring.factories`，加载接口实现类。
- **SpringBoot 自动配置核心底层**。⚠️ SPI 只实例化，不自动注册为 Bean，需配合后置处理器。

```properties
# META-INF/spring.factories
com.example.CustomLoader=com.example.CustomLoaderImpl
```
```java
List<CustomLoader> list = SpringFactoriesLoader.loadFactories(CustomLoader.class, classLoader);
```

---

### 11 种方式总表

| # | 方式 | 一句话 | 场景 |
|---|------|--------|------|
| 1 | XML `<bean>` | 标签声明 | 老旧项目 |
| 2 | XML + scan | XML 开扫描 | 过渡 |
| 3 | `@Component` + `@Bean` | 纯注解 | **日常最常用** |
| 4 | `@Import(Class)` | 直接导入 | 无注解类 |
| 5 | `ImportSelector` | 批量导入 | starter |
| 6 | `ImportBeanDefinitionRegistrar` | 手动构建 BD | Mybatis Mapper 扫描 |
| 7 | `ctx.register()` | 运行时注册 | 条件动态 |
| 8 | `FactoryBean` | 复杂工厂 | 连接池 |
| 9 | `BeanDefinitionRegistryPostProcessor` | 全局后置 | 框架扩展 |
| 10 | SPI | 配置文件加载 | 自动配置 |

## 二、@Configuration 核心细节

### proxyBeanMethods（Full vs Lite）
- **true（默认 Full）**：CGLIB 代理，内部 `@Bean` 方法互相调用返回同一单例。
- **false（Lite）**：无代理，每次调用都 `new` 新对象，**启动更快**。无内部互相调用时优先使用。

```java
@Configuration(proxyBeanMethods = true)   // Full：有代理
@Configuration(proxyBeanMethods = false)  // Lite：无代理，更快
```

## 三、Bean 加载控制

### 编程式（if + register）
```java
if (loadBean) { ctx.register(TestBean.class); }  // refresh 前判断
ctx.refresh();
```

### 注解式（@Conditional 系列）⭐ 高频

| 注解 | 含义 |
|------|------|
| `@ConditionalOnClass` | classpath 有指定类才创建 |
| `@ConditionalOnMissingBean` | 容器没有该 Bean 才创建（**最常用**） |
| `@ConditionalOnProperty` | 配置项匹配才创建 |
| `@ConditionalOnBean` | 容器有指定 Bean 才创建 |

```java
@Bean
@ConditionalOnMissingBean                    // 缺省时才创建默认 Bean
@ConditionalOnProperty(prefix="demo", name="enable", havingValue="true")
public DemoBean demoBean() { return new DemoBean(); }
```

## 四、Bean 依赖配置

| 方式 | 说明 |
|------|------|
| 构造器注入（**推荐**） | `final` 修饰，强制不可为空 |
| `@Autowired` 属性注入 | 不推荐 |
| `@Autowired(required=false)` | 可选依赖 |
| `@DependsOn("xxx")` | 强制指定创建顺序 |
| `@PostConstruct` / `@PreDestroy` | 初始化/销毁回调 |

```java
// 构造器注入（推荐）
private final AService aService;
public BService(AService aService) { this.aService = aService; }

// 强制顺序
@Component
@DependsOn("aService")  // AService 先创建
public class CService { }
```

## 五、SpringBoot 自动配置原理

### 一句话
引入 starter → SpringBoot 自动创建默认 Bean → 用户可覆盖。

### 核心流程
```
@EnableAutoConfiguration
  → @Import(AutoConfigurationImportSelector.class)
    → SpringFactoriesLoader 读 META-INF/spring.factories
      → 加载 XXXAutoConfiguration
        → @Conditional 判断条件
          → 满足就 @Bean 注册
```

### 关键文件
```properties
# META-INF/spring.factories
org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
com.example.DemoRedisAutoConfiguration
```

### 典型自动配置类
```java
@Configuration
@ConditionalOnClass(DemoRedisTemplate.class)           // 类存在才生效
@EnableConfigurationProperties(DemoRedisProperties.class)
public class DemoRedisAutoConfiguration {
    @Bean
    @ConditionalOnMissingBean                           // 用户没定义才创建默认
    public DemoRedisTemplate demoRedisTemplate(DemoRedisProperties p) {
        return new DemoRedisTemplate(p.getHost(), p.getPort());
    }
}
```

### 属性绑定
```java
@ConfigurationProperties(prefix = "demo.redis")
public class DemoRedisProperties {
    private String host = "127.0.0.1";  // 默认值
    private int port = 6379;
}
```
```yaml
# application.yml
demo.redis.host: 192.168.1.100
```

## 六、面试重点速查

| 问题 | 答案 |
|------|------|
| `@Component` vs `@Bean` | 自己写的用 `@Component`；第三方用 `@Bean` |
| `BeanFactory` vs `FactoryBean` | BeanFactory 是容器；FactoryBean 是造 Bean 的工厂 |
| `ImportSelector` vs `ImportBeanDefinitionRegistrar` | Selector 返回类名让 Spring 构建；Registrar 手动构建 BD |
| Registrar vs `BeanDefinitionRegistryPostProcessor` | Registrar 随 `@Import` 局部触发；PostProcessor 全局后置 |
| Full vs Lite | true 有代理保证单例；false 无代理启动快 |
| 自动配置原理 | `@Import` → SPI 读 `spring.factories` → `@Conditional` → `@Bean` |

### 知识点串联
```
自动配置 = @Import + ImportSelector + @Conditional + @Bean + SPI
     ↑ 前面所有知识点的最终落脚点
```
