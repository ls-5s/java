# 一、缓存基础（第104课）

## 1.1 核心知识点

缓存是**用内存高速介质暂存热点数据**、以空间换时间的技术。

| 作用 | 说明 |
|------|------|
| 提升响应速度 | 内存微秒级 vs MySQL 磁盘毫秒级，快几十到上千倍 |
| 削减数据库压力 | 高频查询命中缓存，减少 90%+ SQL 请求 |
| 提升并发能力 | Redis 单机可支撑上万 QPS |
| 增强可用性 | 数据库抖动时热点数据仍可从缓存返回 |

**适用**：频繁查询、极少修改的数据（商品详情、字典配置、分类列表）

**不适用**：强实时一致性数据（金融余额）、访问量极低的冷数据

### 文件：`src/main/java/com/example/demo/service/ProductService.java`

```java
import org.springframework.cache.annotation.CacheEvict;
import org.springframework.cache.annotation.Cacheable;
import org.springframework.stereotype.Service;
import javax.annotation.Resource;

@Service
public class ProductService {

    @Resource
    private ProductMapper productMapper; // 数据库 Mapper

    /**
     * 根据 ID 查询商品（带缓存）
     * value = "product"    → 缓存分组名，一组缓存共用一个分组
     * key = "#id"          → 缓存键，用方法入参 id 作为 key（SpEL 表达式）
     * unless = "#result == null" → 返回 null 时不缓存，防止缓存空值
     */
    @Cacheable(value = "product", key = "#id", unless = "#result == null")
    public Product getProductById(Long id) {
        // 只有缓存未命中时才会执行到这里
        System.out.println("执行数据库查询！");
        return productMapper.selectById(id); // 查询结果会自动存入缓存
    }

    /**
     * 更新商品，同步清除缓存
     * key = "#product.id" → 用入参对象的 id 属性作为缓存键
     * 方法执行完后，product 分组下对应 key 的缓存会被删除
     */
    @CacheEvict(value = "product", key = "#product.id")
    public void updateProduct(Product product) {
        productMapper.updateById(product); // 先更新数据库，再清缓存
    }
}
```

## 1.3 方案2：手动 Redis 编程式缓存

### 文件：`src/main/java/com/example/demo/service/ProductManualCacheService.java`

```java
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.stereotype.Service;
import javax.annotation.Resource;
import java.util.concurrent.TimeUnit;

@Service
public class ProductManualCacheService {

    @Resource
    private RedisTemplate<String, Object> redisTemplate; // Redis 操作模板
    @Resource
    private ProductMapper productMapper;                 // 数据库 Mapper

    /**
     * 手动控制缓存查询流程（不用注解，自己写逻辑）
     */
    public Product getProduct(Long id) {
        // 拼接缓存 key：product:1
        String cacheKey = "product:" + id;

        // 第1步：先查 Redis 缓存
        Product cacheProduct = (Product) redisTemplate.opsForValue().get(cacheKey);
        if (cacheProduct != null) {
            return cacheProduct; // 缓存命中，直接返回，不走数据库
        }

        // 第2步：缓存未命中，查数据库
        Product dbProduct = productMapper.selectById(id);
        if (dbProduct != null) {
            // 第3步：写入缓存，设置 10 分钟过期时间
            // 过期时间很重要！防止缓存无限膨胀占满内存
            redisTemplate.opsForValue().set(cacheKey, dbProduct, 10, TimeUnit.MINUTES);
        }
        return dbProduct;
    }
}
```

# 二、Spring Cache 详解（第105课）

## 2.1 核心知识点

Spring Cache 是 Spring 提供的**缓存抽象层**，通过注解加缓存逻辑，底层可切换 Redis / EHCache / Caffeine。

| 注解 | 作用 | 行为 |
|------|------|------|
| `@Cacheable` | 查询缓存 | 命中返回缓存，未命中执行方法并回填 |
| `@CacheEvict` | 删除缓存 | 删除/更新数据时清除缓存 |
| `@CachePut` | 强制刷新 | **永远执行方法**并更新缓存 |

> `@Cacheable` vs `@CachePut`：前者命中不执行方法，后者永远执行方法。
> 注意：同类内部方法调用（`this.xxx()`）AOP 不生效。

## 2.2 完整代码

### 文件：`pom.xml`

```xml
<!-- spring-boot-starter-cache：Spring Cache 抽象层 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>
<!-- spring-boot-starter-data-redis：Redis 客户端驱动 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
```

### 文件：`src/main/java/com/example/demo/CacheApplication.java`

```java
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.cache.annotation.EnableCaching;

@SpringBootApplication

```

### 文件：`src/main/java/com/example/demo/service/GoodsService.java`

```java
import org.springframework.cache.annotation.CacheEvict;
import org.springframework.cache.annotation.Cacheable;
import org.springframework.cache.annotation.CachePut;
import org.springframework.stereotype.Service;
import javax.annotation.Resource;

@Service
public class GoodsService {

    @Resource
    private GoodsMapper goodsMapper; // 数据库 Mapper

    /**
     * @Cacheable：查询时自动走缓存
     * 缓存命中 → 直接返回，不执行方法体
     * 缓存未命中 → 执行方法体查库，返回值自动存入缓存
     */
    @Cacheable(value = "goods", key = "#id", unless = "#result == null")
    public Goods getById(Long id) {
        System.out.println("执行数据库查询！");
        return goodsMapper.selectById(id);
    }

    /**
     * @CachePut：永远执行方法，并用返回值更新缓存
     * 与 @Cacheable 关键区别：@Cacheable 命中不执行方法，@CachePut 永远执行
     * 适用场景：更新数据后想让缓存也同步更新
     */
    @CachePut(value = "goods", key = "#goods.id")
    public Goods updateGoods(Goods goods) {
        goodsMapper.updateById(goods);
        return goods; // 返回值会更新到缓存中
    }

    /**
     * @CacheEvict：方法执行后删除缓存
     * 适用场景：删除数据时同步清除缓存，防止脏数据
     */
    @CacheEvict(value = "goods", key = "#id")
    public void deleteGoods(Long id) {
        goodsMapper.deleteById(id);
    }

    /**
     * allEntries = true：清空 goods 分组下的全部缓存
     * 适用场景：批量操作后需要全部刷新缓存
     */
    @CacheEvict(value = "goods", allEntries = true)
    public void clearAllCache() {
        // 空方法，注解本身完成缓存清除
    }
}
```

# 三、手机验证码案例（第106-107课，Redis 实战）

## 3.1 业务流程

1. **发送验证码**：手机号作为 Key、验证码作为 Value 存入 Redis，5分钟过期，60秒内禁止重复发送
2. **校验验证码**：从 Redis 取出对比，成功则删除验证码防止复用

## 3.2 完整代码

### 文件：`src/main/java/com/example/demo/controller/SmsController.java`

```java
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import javax.annotation.Resource;
import java.util.Random;
import java.util.concurrent.TimeUnit;

@RestController
public class SmsController {

    @Resource
    private RedisTemplate<String, String> redisTemplate; // Redis 操作模板

    // Redis Key 前缀，用于区分不同业务
    private static final String CODE_KEY_PREFIX = "sms:code:";   // 验证码 key 前缀
    private static final String LIMIT_KEY_PREFIX = "sms:limit:"; // 限流 key 前缀
    private static final long CODE_TTL = 5;      // 验证码有效期：5 分钟
    private static final long LIMIT_TTL = 60;    // 发送冷却期：60 秒

    /**
     * 106 生成 & 发送验证码
     * @param phone 手机号
     * @return 发送结果
     */
    @GetMapping("/sms/send")
    public String sendCode(@RequestParam String phone) {
        // 拼接限流 key：sms:limit:13800138000
        String limitKey = LIMIT_KEY_PREFIX + phone;

        // 检查 60 秒冷却时间，防止恶意频繁发送
        if (Boolean.TRUE.equals(redisTemplate.hasKey(limitKey))) {
            return "操作频繁，请稍后再试";
        }

        // 生成 6 位数字验证码（000000 ~ 999999）
        String code = String.format("%06d", new Random().nextInt(1000000));

        // 拼接验证码 key：sms:code:13800138000
        String codeKey = CODE_KEY_PREFIX + phone;

        // 验证码存入 Redis，5 分钟后自动过期
        redisTemplate.opsForValue().set(codeKey, code, CODE_TTL, TimeUnit.MINUTES);
        // 限流标记存入 Redis，60 秒后自动过期
        redisTemplate.opsForValue().set(limitKey, "1", LIMIT_TTL, TimeUnit.SECONDS);

        // 真实环境调用第三方短信接口发送，这里打印到控制台方便调试
        System.out.println("手机号：" + phone + "，验证码：" + code);
        return "验证码发送成功（调试：" + code + "）";
    }

    /**
     * 107 验证码校验
     * @param phone 手机号
     * @param code  用户输入的验证码
     * @return 校验结果
     */
    @GetMapping("/sms/verify")
    public String verifyCode(@RequestParam String phone, @RequestParam String code) {
        // 拼接验证码 key
        String codeKey = CODE_KEY_PREFIX + phone;

        // 从 Redis 获取真实的验证码
        String realCode = redisTemplate.opsForValue().get(codeKey);

        if (realCode == null) {
            return "验证码不存在或已过期"; // key 已过期或未发送过
        }
        if (!realCode.equals(code)) {
            return "验证码错误"; // 用户输入的验证码不匹配
        }

        // 校验成功，立即删除验证码，防止同一验证码被重复使用
        redisTemplate.delete(codeKey);
        return "校验成功";
    }
}
```

## 3.3 接口测试

```
GET /sms/send?phone=13800138000
GET /sms/verify?phone=13800138000&code=654321
```

### Redis Key 设计

| Key | 用途 | TTL |
|-----|------|-----|
| `sms:code:{phone}` | 验证码 | 5 分钟 |
| `sms:limit:{phone}` | 发送限流 | 60 秒 |

# 四、Redis 数据淘汰策略

## 4.1 核心知识点

Redis 内存达到 `maxmemory` 上限时触发淘汰，共 8 种策略：

| 策略 | 范围 | 行为 |
|------|------|------|
| `noeviction` | — | 默认策略，不淘汰，新增直接报错 |
| `allkeys-lru` | 所有 key | 淘汰**最少最近使用**（最常用） |
| `allkeys-lfu` | 所有 key | 淘汰**访问频次最低**（新版本推荐） |
| `allkeys-random` | 所有 key | 随机淘汰 |
| `volatile-lru` | 带 TTL 的 key | 淘汰最少最近使用 |
| `volatile-lfu` | 带 TTL 的 key | 淘汰访问频次最低 |
| `volatile-random` | 带 TTL 的 key | 随机淘汰 |
| `volatile-ttl` | 带 TTL 的 key | 淘汰**剩余存活时间最短** |

> `allkeys`：所有 key 参与淘汰 | `volatile`：仅带过期时间的 key
> 生产推荐：普通缓存 `allkeys-lru`，追求冷热区分 `allkeys-lfu`

## 4.2 配置方式

### 方式1：redis.conf

```properties
maxmemory 1gb
maxmemory-policy allkeys-lru
```

### 方式2：命令行

```redis
CONFIG GET maxmemory-policy
CONFIG SET maxmemory-policy allkeys-lru
CONFIG SET maxmemory 1G
```

### 方式3：Java 代码

### 文件：`src/main/java/com/example/demo/RedisEvictDemo.java`

```java
import redis.clients.jedis.Jedis;

public class RedisEvictDemo {
    public static void main(String[] args) {
        // try-with-resources：自动关闭 Jedis 连接
        try (Jedis jedis = new Jedis("127.0.0.1", 6379)) {
            // 设置最大内存上限 100MB
            jedis.configSet("maxmemory", "100mb");
            // 设置淘汰策略：所有 key 范围内，淘汰最少最近使用的
            jedis.configSet("maxmemory-policy", "allkeys-lru");

            // 查询当前策略：configGet 返回 List，第0个是 key，第1个是 value
            String policy = jedis.configGet("maxmemory-policy").get(1);
            System.out.println("当前淘汰策略：" + policy);
        }
    }
}
```

# 五、Spring Cache 切换缓存供应商

> 核心思想：业务代码**完全不动**，只改依赖 + 配置即可切换底层缓存。

## 5.1 EHCache 本地缓存（第108课）

### 适用场景：单机项目，不想部署 Redis

### 文件：`pom.xml`

```xml

    <artifactId>ehcache</artifactId>
</dependency>
<!-- Spring Cache 抽象层（必选） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>
```

### 文件：`src/main/resources/application.yml`

```yaml

  cache:
    type: ehcache               # 指定缓存实现为 EHCache（代替 Redis）
    ehcache:
      config: classpath:ehcache.xml  # EHCache 配置文件路径
```

### 文件：`src/main/resources/ehcache.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xmlns="http://www.ehcache.org/v3"
        xsi:schemaLocation="http://www.ehcache.org/v3 https://www.ehcache.org/schema/ehcache-core-3.0.xsd">

    <!-- 默认缓存模板：其他缓存可以继承这个模板，避免重复配置 -->
    <cache-template name="defaultTemplate">
        <expiry>
            <ttl unit="minutes">5</ttl>   <!-- 缓存 5 分钟后过期 -->
        </expiry>
        <resources>
            <heap unit="entries">1000</heap> <!-- 最大缓存 1000 条数据 -->
        </resources>
    </cache-template>

    <!-- goods 缓存：继承默认模板 -->
    <cache alias="goods" uses-template="defaultTemplate"/>
</config>
```

```java
import org.springframework.cache.annotation.CacheEvict;
import org.springframework.cache.annotation.Cacheable;
import org.springframework.stereotype.Service;
import javax.annotation.Resource;

@Service
public class GoodsServiceImpl implements GoodsService {
```

### 文件：`src/main/java/com/example/demo/config/RedisCacheConfig.java`

```java
import org.springframework.cache.annotation.EnableCaching;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.cache.RedisCacheConfiguration;
import org.springframework.data.redis.cache.RedisCacheManager;
import org.springframework.data.redis.connection.RedisConnectionFactory;
import org.springframework.data.redis.serializer.GenericJsonRedisSerializer;
import org.springframework.data.redis.serializer.RedisSerializationContext;

import java.time.Duration;
import java.util.HashMap;
import java.util.Map;

@Configuration
@EnableCaching
public class RedisCacheConfig {

    /**
     * 自定义 RedisCacheManager，替换默认的 Jdk 序列化
     * 目的：让缓存 value 以 JSON 格式存储，可读性好、跨语言兼容
     */
    @Bean
    public RedisCacheManager cacheManager(RedisConnectionFactory factory) {
        // 使用 GenericJsonRedisSerializer 序列化缓存值（JSON 格式）
        GenericJsonRedisSerializer<Object> serializer = new GenericJsonRedisSerializer<>(Object.class);

        // 默认缓存配置
        RedisCacheConfiguration defaultConfig = RedisCacheConfiguration.defaultCacheConfig()
                .entryTtl(Duration.ofMinutes(5))        // 默认 5 分钟过期
                .serializeValuesWith(RedisSerializationContext.SerializationPair.fromSerializer(serializer)) // JSON 序列化
                .disableCachingNullValues();             // 不缓存 null 值

        // 不同缓存分组可以单独设置过期时间
        Map<String, RedisCacheConfiguration> cacheMap = new HashMap<>();
        cacheMap.put("goods", defaultConfig.entryTtl(Duration.ofMinutes(10))); // goods 分组 10 分钟过期

        return RedisCacheManager.builder(factory)
                .cacheDefaults(defaultConfig)           // 默认配置
                .withInitialCacheConfigurations(cacheMap) // 各分组个性化配置
                .build();
    }
}
```

## 6.3 JetCache 方法缓存：完整 CRUD（第114课）

> `@Cached`（查询）、`@CacheInvalidate`（删除）、`@CacheUpdate`（更新）

### 文件：`src/main/java/com/example/demo/service/UserService.java`

```java
import com.alicp.jetcache.anno.CacheInvalidate;
import com.alicp.jetcache.anno.Cached;
import com.alicp.jetcache.anno.CacheType;
import org.springframework.stereotype.Service;
import javax.annotation.Resource;

@Service
public class UserService {

    @Resource
    private UserMapper userMapper; // 数据库 Mapper

    /**
     * @Cached：查询缓存
     * 缓存命中 → 直接返回缓存值，不执行方法
     * 缓存未命中 → 执行方法查数据库，结果自动写入缓存
     */
    @Cached(
            name = "user:info:",
            key = "#userId",
            expire = 300,              // 缓存 5 分钟
            cacheType = CacheType.REMOTE
    )
    public UserDTO getUser(Long userId) {
        return userMapper.selectById(userId);
    }

    /**
     * @CacheInvalidate：更新数据后删除缓存
     * 方法执行完后，自动删除对应 key 的缓存
     * 下次查询时缓存未命中，会重新查库并回填最新数据
     */
    @CacheInvalidate(name = "user:info:", key = "#userId")
    public void updateUser(Long userId, UserDTO dto) {
        userMapper.updateById(dto); // 先更新数据库，后清缓存
    }

    /**
     * 删除数据 + 删除缓存（同 @CacheInvalidate）
     */
    @CacheInvalidate(name = "user:info:", key = "#userId")
    public void deleteUser(Long userId) {
        userMapper.deleteById(userId); // 先删数据库，后清缓存
    }
}
```

# 七、J2Cache 两级缓存（第115-116课）

> J2Cache 是**专门做两级缓存**的框架：L1 本地 Caffeine + L2 Redis 远程。
> 与 JetCache 区别：J2Cache 天生主打两级，自带集群缓存广播同步。

## 7.1 基本操作（第115课）

### 文件：`pom.xml`

```xml

</dependency>
```

### 文件：`src/main/java/com/example/demo/service/J2CacheDemoService.java`（方式① 原生 API 手动操作）

```java
import net.oschina.j2cache.CacheChannel;
import org.springframework.stereotype.Service;
import javax.annotation.Resource;

@Service
public class J2CacheDemoService {

    @Resource
    private CacheChannel cacheChannel; // J2Cache 核心操作类，相当于"缓存通道"

    private static final String REGION = "user"; // region：缓存区域，用于区分不同业务

    /**
     * 写入两级缓存
     * region → 缓存区域（类似 SpringCache 的 value）
     * key    → 缓存键
     * value  → 缓存数据
     * 300    → 过期秒数
     * 自动写入 L1（本地 Caffeine）+ L2（Redis）
     */
    public void setUser(Long userId, UserDTO dto) {
        cacheChannel.set(REGION, userId.toString(), dto, 300);
    }

    /**
     * 查询缓存（优先查 L1 本地，未命中再查 L2 Redis）
     * asObject(UserDTO.class) → 将缓存值反序列化为指定类型
     */
    public UserDTO getUser(Long userId) {
        return cacheChannel.get(REGION, userId.toString()).asObject(UserDTO.class);
    }

    /**
     * 删除缓存（同时清除 L1 和 L2）
     * 集群环境通过广播机制通知其他节点同步清除本地缓存
     */
    public void removeUser(Long userId) {
        cacheChannel.evict(REGION, userId.toString());
    }
}
```

```java
import org.quartz.JobDetail;
import org.quartz.Trigger;
import org.quartz.SimpleScheduleBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import static org.quartz.JobBuilder.newJob;       // 构建 JobDetail
import static org.quartz.TriggerBuilder.newTrigger; // 构建 Trigger

@Configuration
public class QuartzConfig {

    /**
     * JobDetail：绑定任务类，给任务起名、分组
     * withIdentity("demoTask", "taskGroup") → 任务名为 demoTask，分组为 taskGroup
     * storeDurably() → 即使没有 Trigger 绑定也保留任务定义
     */
    @Bean
    public JobDetail demoJobDetail() {
        return newJob(DemoTask.class)              // 绑定 DemoTask 任务类
                .withIdentity("demoTask", "taskGroup") // 任务名 + 分组（唯一标识）
                .storeDurably()                    // 持久化任务定义
                .build();
    }

    /**
     * Trigger：定义任务执行规则
     * 这里使用 SimpleSchedule：每隔 5 秒执行一次，永不停止
     */
    @Bean
    public Trigger demoTrigger() {
        SimpleScheduleBuilder schedule = SimpleScheduleBuilder
                .simpleSchedule()
                .withIntervalInSeconds(5)  // 每隔 5 秒触发一次
                .repeatForever();          // 一直重复，不停止

        // 如果用 Cron 表达式控制定时，改为：
        // CronScheduleBuilder.cronSchedule("0/5 * * * * ?")  // 每 5 秒执行

        return newTrigger()
                .withIdentity("demoTrigger", "triggerGroup") // 触发器名 + 分组
                .forJob(demoJobDetail())                     // 绑定到哪个任务
                .withSchedule(schedule)                      // 绑定执行规则
                .build();
    }
}
```

```java
import org.quartz.*;
import org.springframework.stereotype.Service;
import javax.annotation.Resource;

@Service
public class QuartzManagerService {

    @Resource
    private Scheduler scheduler; // Quartz 调度器，核心操作类

    /**
     * 动态新增任务（运行时添加，无需重启）
     */
    public void addTask() throws Exception {
        JobDetail jobDetail = newJob(DemoTask.class)
                .withIdentity("task1", "group1") // 任务唯一标识
                .storeDurably()
                .build();

        Trigger trigger = newTrigger()
                .withIdentity("trigger1", "group1")
                .withSchedule(CronScheduleBuilder.cronSchedule("0/10 * * * * ?")) // 每 10 秒
                .build();

        scheduler.scheduleJob(jobDetail, trigger); // 注册到调度器
    }

    /**
     * 暂停任务（任务定义保留，暂停触发）
     */
    public void pauseTask() throws Exception {
        JobKey jobKey = JobKey.jobKey("task1", "group1"); // 通过名称和分组定位任务
        scheduler.pauseJob(jobKey); // 暂停
    }

    /**
     * 删除任务（彻底移除任务定义 + 触发器）
     */
    public void deleteTask() throws Exception {
        JobKey jobKey = JobKey.jobKey("task1", "group1");
        scheduler.deleteJob(jobKey); // 删除
    }
}
```

```java
import lombok.extern.slf4j.Slf4j;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
import java.time.LocalDateTime;

@Slf4j
@Component  // 必须交给 Spring 管理，@Scheduled 才会生效
public class DemoScheduledTask {

    /**
     * fixedRate = 5000：每隔 5 秒执行一次
     * 从上一次执行开始时计时，不管上次是否完成
     * 如果方法执行超过 5 秒，下次会排队等待
     */
    @Scheduled(fixedRate = 5000)
    public void rateTask() {
        log.info("fixedRate定时执行：{}", LocalDateTime.now());
    }

    /**
     * cron = "0/10 * * * * ?"：每 10 秒执行一次
     * cron 表达式格式：秒 分 时 日 月 周
     * 0/10 = 从第0秒开始，每隔10秒
     */
    @Scheduled(cron = "0/10 * * * * ?")
    public void cronTask() {
        log.info("cron定时执行：{}", LocalDateTime.now());
    }
}
```

## 8.3 Quartz vs @Scheduled

| 特性 | @Scheduled | Quartz |
|------|-----------|--------|
| 配置复杂度 | 零配置 | 需配置类 |
| 动态增删改任务 | 不支持 | 支持 |
| 任务持久化 | 不支持 | 支持（数据库） |
| 集群防重复 | 不支持 | 支持 |
| 适用场景 | 简单固定定时 | 复杂动态任务 |

# 九、关键总结

## 9.1 缓存选型

| 场景 | 推荐方案 |
|------|---------|
| 单机简单缓存 | Spring Cache + Caffeine / EHCache |
| 集群/微服务 | Spring Cache + Redis |
| 需要多级缓存 | JetCache BOTH 或 J2Cache |
| 需要丰富缓存控制 | JetCache（支持刷新、穿透防护） |
| 老系统维护 | Memcached |

## 9.2 开发避坑

| # | 坑 | 正确做法 |
|---|-----|---------|
| 1 | 缓存没设过期时间 | 必须设 TTL，防止内存无限膨胀 |
| 2 | 更新数据没清缓存 | 写操作后同步清理缓存，保证一致性 |
| 3 | 同类方法调用注解失效 | AOP 只拦截外部调用，内部 `this.xxx()` 不走代理 |
| 4 | 集群用本地缓存 | 集群必须用分布式缓存（Redis），否则各节点数据不一致 |
| 5 | `volatile-*` 策略 + 无 TTL key | 无过期时间的 key 不会被淘汰，最终 OOM |
